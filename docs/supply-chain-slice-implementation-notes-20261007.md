# Supply Chain slice 实现说明 · 2026-10-07

**性质**：对 `docs/automage-website-implementation-handoff-20261007.md` 第一阶段（Supply Chain vertical slice）的实现回执。handoff 仍然是 canonical contract，本文只记录做了什么、哪些设计假设按证据调整过、还剩什么。
**状态**：已实现，位于 `feat/homepage-vnext` 工作区，**未提交**。

## 1. 体验结构

`/scenarios/supply-chain` 是一项工作的 14 天世界，访客的身份是供应链负责人。

- **时间轴**（页面浏览控件，深色）：逐天前进，可以点回任何走过的一天。第 3 天、第 6 天如果需要访客决定，前进会被挡住，按钮变成「等你签批 v1 ↓」「等你重新决定 ↓」，点击会跳到需要操作的位置。键盘 ←/→ 可用。
- **工作单**（业务对象，亮纸面）：委托 7 条 → 当天的变化（每条都写「因为」）→ 库存测算图 → 依据（事实 / 推断 / 还不知道，每条都能点开看来源）→ 决定（v1、v2 带着各自当时的前提保留）→ 落实（任务、回执）→ 关闭（按委托第 7 条）。
- **桌面栏**：你的待办（等你签批 / 退回给你 / 报备卡），以及当天的消息流（系统、同事、AutoMage、你的签批用四种样式区分）。
- **核心时刻（第 6 天）**：供应商 B 质检不合格，只能交 60%。v1 中这一条前提被划掉，工作重新打开并回到访客手上，界面同时列出「v1 为什么成立」和「现在变了什么」。访客签批 v2 后，执行、回执和关闭都继续在同一张工作单里进行。
- **拆开看**：用标注把页面上的元素分成三层：企业原有、AutoMage 做的、委托边界。可以单独查看某一层。只做标注，不另起叙事。
- **改规矩重放**（情景模拟 · 产品方向）：把委托第 5 条改成「额外成本 ≤ 已批金额 5% 的自行调整、事后报备」，然后重放第 6 天。前 5 天、v1、第 6 天的事件都相同。这次不会回到访客面前，只产生一张报备卡，并说明没有采用的选项和理由。页面不提供保存，也不出现配置成功的提示，标注常驻。第 6 天退回发生之后即可进入。

## 6. 视觉轮（2026-10-07，依据 owner 对实际渲染的评审）

**触发**：owner 看了实际页面。能力详情页"风格统一，但所有文字堆在一起，没有主次"；供应链页"有新意，但明显是两套排版和设计风格拼出来的"。产品叙事、三页职责和供应链的交互机制都不变，这一轮只重新组织注意力。

**根因（从截图和代码判断）**

- 能力详情页没有视觉主角。产物预览是一张和背景同色系的暗卡片，画的还是"比较什么 / 结果里能看到"这样的说明表，不是产物本身。其余七段都是同一种标题加灰字，条件栏又是一张卡片。
- 供应链页的亮面本身成立，割裂来自三处：
  - 米色纸面是全站唯一的暖色。
  - 纸面内部和右栏各有一套字体用法：中文用了等宽字体，还有表格线和方块套方块。
  - 顶部是落地页式的两行大标题加"怎么看这一页"图例，下面紧接一条像第二个导航栏的浮动工具栏。
- 所以"暗桌面 + 亮纸张"的结构保留（一块亮面 = 工作本身），执行方式要改。

**改动**

- 供应链：
  - 顶部改为一行标题的案例头，演示与已实现说明放在右侧旁注，去掉图例。
  - 时间轴改成贴在地面上的一条刻度带，按钮与全站按钮同款。
  - 工作单改为冷白，中文不再用等宽字体；去掉内部的嵌套卡片、数字方块和记录卡片，只保留"等你决定"和"重新打开"这两块需要你动手的面板。
  - 工作单的顺序改为：今天的变化 → 待你决定的面板 → 第 14 天的关闭 → 委托 → 测算 → 依据 → 决定 → 落实。从第 1 天起，桌面端也只显示"回到你这里"的两条委托和今天新增的依据，都可以展开；打开"拆开看"时全部显示。
  - 右栏去掉卡片容器，改成地面上的分段。待办条目也不再是第二块亮面：只留一条左侧细线和一个状态小标签。
  - 时间轴上的"等你签批 v1 ↓"仍是浏览控件，用全站主按钮的蓝色加一圈等待光晕，不再借用亮面颜色。"拆开看"和"改规矩重放"改成单行按钮，去掉了看不清的小字说明和三色图标；发现入口靠关键时刻出现的邀请，这一点没有复测。
  - 第 6 天的红色只留给"坏掉的那一处"：状态标签、"重新打开"标记、被划掉的前提和那句变化本身。"重新打开"面板改用和 v1 决定相同的深蓝边框，"v1 为什么成立 / 现在变了什么"改为细线分隔的两栏，不再是粉色和灰色的嵌套框。
  - 消息流里的系统预警不再用琥珀色，因为琥珀在这一页表示"还不知道"。
- 能力详情（`SkillDetail.tsx`、`OutcomePreview.tsx`、`MarketPage.module.css`）：
  - 产物预览改为页面唯一的亮面"你会拿到"。候选对照画成一张填好的示例表：示例需求加三个候选，标"演示"，并注明"演示数据，不是真实查询结果"，供应商做了匿名处理。其余几种产物也按产物本身的形态画。
  - 英文 mono 眉标改为中文元信息。
  - 产物下方用一行写清"你提供 / 从资料到交付 / 范围与边界 / 接入条件"。
  - 收录情况和原始标识移到页尾一行，去掉重复的选择说明段落。
  - 没有专门说明的 178 项能力，亮面只写产出名称，并如实说明"目前只收录了技能说明"。
- 修复：上一轮移动端的重复样式把"看全部依据"按钮隐藏了，现已恢复。

**独立复核**：第一版改完后，请一个没有参与设计的评审只看截图做了批评，并据此改了第二版。该评审指出：灰色占位行像"加载中"，第 6 天红色过多，亮面颜色被按钮和待办借用，时间轴右侧按钮像开发者工具，决策面板嵌套过深。该评审另认为能力页下方四列"分量相同"，没有采纳：这四列是主角下方并列的使用条件，本来就该同级。

**从这轮修改里观察到的做法**：这些是观察，没有升格为全局 Design System，也没有写成规范。

1. 暗色地面承载页面的声音：上下文、说明、控制和当天消息。亮面只给工作对象本身，比如供应链的工作单、能力页的产物，一个视口最多一块。
2. 地面和亮面用同一套字体角色：页面标题、对象标题、区块标题、标签、正文、元信息。等宽字体只用于编号和时间，不排中文。
3. 只有对象本身和"需要你动手的决定"有容器，其余用留白、细线和标签分组。
4. 先放"今天变了什么 / 你会拿到什么"，常设内容收成一行，可以展开。
5. 两页的语义色一致：蓝 = AutoMage，琥珀 = 未知，红 = 失效，绿 = 已核实，深蓝墨 = 人的决定。


## 7. 首页重建（2026-10-07，handoff §4.1）

**触发**：owner 看了 9 月的 `SystemHome`，判断它是一次视觉回退：没有视觉命题，像一个规整的企业 AI 网站。对照三个版本：
- 6 月版：线上 / git `918ab20`。
- 8 月版：从未提交，首次进入 checkpoint `a1d7f0c`。
- 9 月版：`SystemHome`。

结论：8 月已经做过一次"保留视觉机制、替换语义"。9 月为了修"Market 被记成产品"的层级问题，把事件叙事挪进场景页、首页换成抽象版，从此 8 月的视觉机制没有页面继承。handoff §3.2 和 §7.4 已按 owner 决定修订：退役的是六节点环作为固定 ontology 的地位，不是它的表现资产；首页语言改为"视觉能量集中"。

**做法**：代码在 `src/components/home/`（`Home`、`HomeStage`、`WorkObject`、`Track`）和 `src/lib/home-stage.ts`。旧 `SystemHome` 与 8 月组件未删。

- **继承自 8 月版的编排**：
  - 整页像一件工作正在发生；
  - 一个 sticky 舞台，旁边逐段说明；
  - 散落的消息汇成一件事的转化时刻；
  - 路径随滚动绘制，状态随滚动推进。
- **转化时刻**：首屏是第 0–2 天的 8 条消息，WMS 预警最醒目，表示"事情从这里开始"。往下一滚，预警落成工作单的标题，其余消息缩进它们变成的那一行的来源标签；落点不对应任何一行的三条，汇入"下一步"的来源。转化一旦开始就按时间播完，不随滚动停在半空；滚回顶部会倒放。
- **换掉的语义**：环形改成"这件事在谁手上"。
  - 两条泳道：人、AutoMage；中间一条虚线委托边界。
  - 一个 SC-0817 小标签沿路径移动。
  - 线下方写着这一步按的规矩：第 3 天是"新的采购方案：回来签批"，第 6 天是"执行中的任何变化：回来找人"。
  - 最后一段在同一个第 6 天换一条规矩：旧规矩划掉，新规矩出现，路径留在 AutoMage 一侧，只留一张报备卡。这个替换就是标题"规矩由你们定"要演的那件事，标"模拟改写"。
  - 环形、固定节点、发光核心球、粒子、跑马灯、指标都没有带回。
- **主角**：和场景页同一件 SC-0817 缺料，同一组事实、人和来源，数据取自 `supply-chain-world.ts`。来源标签紧跟在被支撑的那句话后面，带"›"提示可以点开；`SourceTag` 的样式拆成自己的 CSS 模块，两页共用。首页只演 4 个时刻，14 天留给场景页。
- **身份**：H1 是通用的（"把工作交给 AutoMage，规矩由你们定"）。首屏同时写明"现在已经能用"和"产品方向"，延续 9 月修好的产品层级。
- **滚动与业务动作**：滚动只推动叙事揭示，不代表访客做了任何业务动作。签批写成"供应链负责人签批"，访客亲手签批留给场景页。所有状态都由滚动位置算出，向上滚会自然倒回。
- **舞台之后保持安静**：
  - 三种角色，每种带着它在舞台上的标记：人那一栏、来源标签、委托边界；
  - 两个门："看这件事完整的 14 天" / "看它还能接哪些工作"；
  - 联系入口；
  - 收纳原 FAQ 的"边界与演示说明"抽屉。
- **降级**：
  - 窄屏（< 1024px）和矮屏（< 620px）不用 sticky 舞台，同一组时刻按顺序放成静态画面。每帧只画那一刻变化的部分，第 2–4 帧各带一条轨迹。
  - 手机上的轨迹用自己的窄几何，不是把宽版缩小。
  - reduced motion 下仍用舞台，但每段直接显示定格状态，没有飞行和过渡。

**滚动方式（owner 对实际滚动的反馈后改；已被下面的第三轮取代）**：
- **问题**：只有右栏固定、左栏是 522px 一段的普通段落时，鼠标滚一格（100px）永远停在两幕之间，左栏同时露出 2–3 幕，时间线也不显眼。
- **核对**：旧版并没有吸附代码；当时"被吸住"的感觉来自环那一节整节固定（pin）加上 Lenis 的平滑滚动。
- **现在的做法**：
  - 舞台是"每幕一屏"的滚动跑道，跑道里的框架始终留在视口；左栏只显示当前一幕的文字，原地切换。
  - 首页恢复 Lenis 平滑滚动，不扩到全站。舞台内一次滚轮手势或一次按键（↓ / PageDown / 空格，反向同理）前进一整幕；滑动期间锁住输入，手势剩下的惯性也忽略，所以一次不会跳过几幕。
  - 舞台上方和下方自由滚动；从下方往上滚会先回到最后一幕。
  - 时间线移到右栏顶部，四个日子是可以点的刻度，当前一幕高亮；每段线都在那一幕落定之前画完。
  - 减少动态效果下用原生滚动，每幕直接定格；手机和矮屏仍按顺序放静态画面。
- **试用开关**：`/?scroll=soft` 是另一种手感，自由滚动，停下后吸到最近一幕，只用于对比。第三轮已和逐幕步进一起删掉。

**独立复核**：第一版完成后，请一位没参与设计的评审只看截图批评，按意见改了第二版。

| 评审意见 | 处理 |
|---|---|
| 首屏没有主角 | 预警放大，作为起点 |
| 转化像收集而不是转化，有的消息凭空消失 | 每条消息缩进它变成的那一行的来源标签 |
| 轨迹像一张指标图 | 加标题"这件事在谁手上"、泳道底色和移动的工作标签；当前事件最亮 |
| 规矩被埋在角落 | 规矩随步骤切换，最后一段做成替换事件 |
| 来源标签不像能点 | 改为紧跟内容，加"›" |
| 标题渐变是 AI 网站的老套路 | 改成纯色 |
| "说一件你们的事"像联系按钮 | 改名"看它还能接哪些工作" |
| 手机没有轨迹，"八条消息"只显示六条 | 补上轨迹，八条全部显示 |

建议"首屏放一张空白的待接手工作单"，没有采纳：会削弱转化。

### 7.1 第三轮：共享 case，不共享 plot（2026-10-08，owner 决定）

**触发**：owner 指出三件事。
- 右栏时间线带来新的理解成本：它替代了常规的滚动条或进度条，占着首页最好的位置，还要写一行字教人怎么点。
- 滚轮步进让首页像"滚轮控制的轮播"：滚一格后约 0.4 秒屏幕上没有变化，滑动中的输入被吞掉，用户会以为没滚动成功。
- 首页按第 0 / 3 / 6 天讲同一件事，和场景页重合；舞台之后的一屏不是精华。

**决定（已写入 handoff §4.1）**：
- 首页舞台按两个产品主张组织，不按日子讲故事，删掉第 3 天签批：
  - 散乱信息如何成为一件 AutoMage 可以承接的工作；
  - 同一个现实变化，在两种委托边界下为什么得到不同结果。
- 完整时间、签批、重新打开、自己改规矩都留给场景页。
- 右栏时间线删除，暂不用右侧圆点或底部进度条替代；先恢复克制的全站滚动条。stage 内是否还需要局部进度提示，等看了渲染结果再定最小形式。
- 舞台之后只留三件事：什么样的工作适合交给它；现在真实做到哪里、哪些是场景或方向；两个出口。

**现在的舞台**（`HomeStage`、`WorkObject` 的 `WorkCard` / `ChangedCard`、`Fork`，数据在 `home-stage.ts`；`Track.tsx` 已删除）：
- **开场**：H1、一段说明、8 条消息。"现在已经能用 / 产品方向"从首屏挪到舞台之后。
- **「把工作交给它」**：消息随滚动飞进工作单。预警落成标题，其余消息缩进各自那一行的来源标签；工作单的状态"AutoMage 跟进中"最后出现。下一步写"按委托交供应链负责人定"，不演签批。
- **「规矩由你们定」**：
  - 工作单折成"执行中：方案 A"和它依赖的那条前提；
  - 第 6 天的变化像前面的消息一样飞进来，落在那条前提上，前提被划掉，状态变成"前提变了"；
  - 然后线从工作单分成两支：一支是"执行中出现任何变化：回来找人确认 → 回到负责人手上"，一支是"额外成本不超过已批金额 5%：自己调整，事后报备 → AutoMage 自己补上（多花 ¥2.0 万，2.2%）"。
  - 事实相同，只有委托里那一条不同；标"产品方向 · 模拟"。
- 两个主张的小标题分别引用 H1 的两半。

**滚动**：
- 删掉逐幕步进、滑动锁、手势尾巴过滤、按键接管和 `?scroll=soft`。
- 舞台仍是固定在视口里的跑道，长 3 屏。滚动位置直接换算成 `--p`，左栏文字的进出、消息飞行、变化落下、分叉绘制都按 `--p` 连续计算：滚多少动多少，往回滚就倒放，不吞任何输入。
- Lenis 只负责平滑滚轮。
- 实测（生产构建）：
  - 滚一格后 4ms 页面已移动，约 50ms 开场文字开始变淡；
  - 90ms 间隔连续滚 3 格，位置依次到 41、115、191，最后停在 300，每格都生效。
- 减少动态效果：不启用 Lenis，每部分直接显示完成状态，在两部分之间的中点切换。

**全站滚动条**：
- `globals.css` 从 5 月 13 日起一直隐藏原生滚动条，现在改成 `scrollbar-width: thin`、半透明灰色滑块，并加 `scrollbar-gutter: stable`，切换页面时不跳动。
- 首页、能力、联系、场景四个页面在 1440 和 390 宽度下都没有横向溢出。
- Safari 不支持这两个标准属性的部分版本会显示系统默认样式，没有专门处理。
