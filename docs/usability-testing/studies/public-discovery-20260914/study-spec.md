# Public discovery and differentiated Skill selection

Status: frozen design; runtime proof pending before launch.

The owner authorized redesign with deliberate selection and grouping of homogeneous Skills. Test whether two fresh business visitors can understand the system, evaluate current outputs/conditions, differentiate related choices and prepare a coherent inquiry.

Roles and task assumptions are coordinator-authored within the authorized product scope. They do not create a new owner approval or release gate. No real contact submission, actual Skill execution or production integration is tested here.

Use two fresh model sessions with no parent conversation, two fresh anonymous browser profiles, and only the respective participant packet. Isolation is best_effort: tool and filesystem restrictions rely partly on prompt discipline. A separate read-only recorder will review scoped public logs after participant termination; no participant receives other roles, source, oracle or previous runs.

Version the runtime by source fingerprint after coordinator functional checks. Collect schema-stable step/event/verdict artifacts outside the repository, review and sanitize before promotion. Close each owned browser; no real business entities are created. Stop on task completion, two attempts without progress on one subgoal, forbidden knowledge or runtime inability. Rate-limit interruptions can be retried with a fresh session and changed backoff while respecting the bounded study.

Iteration cap: 2. Stop early if semantic goals are supported; if a material issue changes implementation, test that issue with a new participant rather than reusing learned context. This study is discovery evidence, not production-ready certification.
